# ЛР 2 — Об'єктно-орієнтована модель розкладу (group_schedule_oop)

Друга лабораторна, варіант 4. Дані й завдання ті самі, що в ЛР 1
(`../lab1`), але тепер вони описані класами: ієрархія типів занять,
домішка (mixin), узагальнене сховище, перелічення, методи розширення,
записи та `switch` зі зразками.

## Запуск

```bash
dart pub get
dart run                                    # демонстрація моделі
dart run example/hash_code_experiment.dart  # == без hashCode
dart run example/consultation_classic.dart  # первинний і класичний конструктор
dart analyze
dart test                                   # 16 тестів
```

| `lib/weekday.dart` | `enum Weekday` |

в тести.

## Чому така структура й такі типи

**`Lesson` — запечатаний клас із трьома підтипами**, а не рядок `kind`.
Тип заняття став частиною системи типів. `switch` по `Lesson` без гілки
`default` компілятор перевіряє на вичерпність: у звіті я додала четвертий
підтип `Seminar`, і компілятор одразу вказав два місця, де його не
враховано. Підтипи ще й мають поліморфний метод `seatsNeeded` (для
лабораторної група ділиться навпіл).
*Альтернатива:* `enum LessonKind` + поле у класі — простіше, але в
перелічення немає окремих полів і методів для кожного варіанта, а
поведінка залишилась би в `switch`.

**Усе незмінне:** поля `final`, конструктор `const`. Рівність за
значенням — `==` разом із `hashCode`: експеримент
`example/hash_code_experiment.dart` показує, що, коли перевизначено лише
`==`, однакові об'єкти опиняються в `Set` як різні (розмір 2 замість 1), а
`contains` повертає `false`.

**Три способи створити заняття.** `Lesson.fromCsv` кидає
`LessonFormatException`; `Lesson.tryParse` повертає `null` (замінює
`readLesson` з ЛР 1); `Lesson.cached` для того самого рядка повертає той
самий об'єкт без повторного розбору. Конструктор не може повернути `null`,
тому «безпечний» розбір довелося зробити статичним методом.

**Домішка `Schedulable on TimeSlot`.** Додає до щотижневих слотів
`weekMinute`, `finishMinutes`, `overlaps`, `nextOccurrence` і підмішана і
до `Lesson`, і до `Consultation`. `on TimeSlot` робить дві речі: дозволяє
домішку лише для нащадків `TimeSlot` і дає їй доступ до `weekday` і
`startMinutes`.
*Альтернатива:* успадкування. Не підходить: в Dart одне успадкування, а
`Lesson` уже вузол запечатаної ієрархії; до того ж поведінка потрібна
лише слотам, що повторюються щотижня.

**`Repository<T extends Identifiable>`.** Обмеження дає право викликати
`item.id`. Без нього (`UnboundedRepository<T>`) код не компілюється:
«The property 'id' can't be unconditionally accessed because the receiver
can be 'null'».

**`enum Weekday`** з номером, скороченою назвою, `isStudyDay`, `next` і
`fromNumber` замінив мапу назв днів і «магічні» числа з ЛР 1: некоректний
день тижня тепер просто неможливо створити.

**Записи** (`LoadSummary`, `({Lesson first, Lesson last})`,
`({int hours, int minutes})`) повертають кілька значень без окремих
класів і розбираються деструктуризацією.
*Альтернатива:* окремий клас під кожне таке значення — зайвий код.

**Методи розширення** (`academicHours`, `byWeekday`, `ofType<T>()` для
списку занять; `isLecturerName`, `masked` для рядка) додають зручні
операції, не змінюючи самі класи й `String`.

**Типи даних, що лишилися:** час — `int` хвилин від півночі, дата —
`DateTime` в UTC (причини в ЛР 1).

## Первинний конструктор (Dart 3.13)

`Consultation` записано з первинним конструктором: поля й конструктор в
одному заголовку класу. Класичний варіант — у
`example/consultation_classic.dart`; поведінка однакова, але 18 рядків
коду проти 13. Побічні ефекти: параметр без `final`/`var` не стає полем, а
лінт `public_member_api_docs` ще не вміє документувати первинний
конструктор, тому в одному місці стоїть `// ignore: public_member_api_docs`.

## Залежності

Для запуску пакетів немає. Для розробки:

| Пакет | Навіщо | Альтернатива |
|---|---|---|
| `lints` | набір `recommended` + суворіші правила в `analysis_options.yaml` | `flutter_lints` — для Flutter, а це чистий Dart |
| `test` | модульні тести моделі (16) | `flutter_test` — працює лише у Flutter |

Зовнішні пакети для моделі не потрібні: рівність, домішки, узагальнення й
перелічення є в самій мові. *Альтернатива для рівності:* пакети `equatable`
або `freezed` генерують `==` і `hashCode`, але тут я перевизначаю їх
вручну, щоб побачити, що буде без `hashCode`.

## `!`, `late`, `dynamic`, `as`

У `lib/` їх немає.

## Що змінилося порівняно з ЛР 1

Тип заняття став підтипом, а не рядком; запис `Lesson` і результат
`Decoded` замінено класом і `Lesson.tryParse`; правила переведено на
`Weekday`; функції для часу стали методами домішки. Обсяг коду бібліотеки
виріс з 406 до 471 рядка (приблизно на 16 %), тестів стало 16 замість 13,
але частину перевірок перенесено з часу виконання на час компіляції.
