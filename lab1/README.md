# ЛР 1 — Розклад занять групи (group_schedule)

Перша лабораторна з Dart, варіант 4. Заняття має шість полів: дисципліна,
викладач, тип (лекція / практика / лабораторна), день тижня, час початку й
номер аудиторії.

Програма читає рядки CSV, відкидає зламані, перевіряє решту на правила,
рахує навантаження, шукає накладки аудиторій і друкує розклад найближчих
занять.

За умовою цієї роботи **класів немає**: уся логіка — на записах (records),
функціях, замиканнях і стандартних колекціях. Класи з'являються в ЛР 2.

## Запуск

```bash
dart pub get
dart run bin/group_schedule.dart 2026-10-15   
dart analyze
dart test                                      
```

Дату можна передати аргументом, щоб вивід можна було відтворити; без неї
береться поточний момент.

## Вхідні дані

Один рядок — одне заняття, поля розділені `;`:

```
дисципліна;викладач;тип;день;час;аудиторія;пар;внесено
Програмування мовою Dart;Петренко О.В.;лекція;1;09:30;287;16;2026-08-28
```

Крім шести полів із завдання, у рядку ще кількість пар за семестр (потрібна
для підрахунку годин) і дата, коли запис внесено (потрібна, щоб порахувати,
скільки днів тому він з'явився).

У `lib/timetable_rows.dart` 18 рядків:

* 12 правильних;
* 4 зламані: бракує поля, «середа» замість цифри дня, час `9.30`,
  неіснуюча дата `2026-02-30`;
* 2 такі, що розбираються, але порушують правила.

## Як влаштований код

У `bin/` лежить лише послідовність викликів, уся логіка — в `lib/`.

| Файл | Що в ньому |
|---|---|
| `bin/group_schedule.dart` | точка входу: кроки по черзі й вивід |
| `lib/group_schedule.dart` | єдиний файл, через який підключається бібліотека |
| `lib/settings.dart` | формат рядка, межі, сітка пар, дозволені типи занять |
| `lib/lesson.dart` | псевдоніми типів: `Lesson`, `Decoded`, `LessonTest`, `LessonOrder`, `LessonRule` |
| `lib/timetable_rows.dart` | вхідні рядки |
| `lib/patterns.dart` | регулярні вирази, маскування прізвища |
| `lib/clock.dart` | розбір часу й дати, арифметика дат |
| `lib/decode.dart` | `readLesson` — розбір рядка без винятків |
| `lib/rules.dart` | правила перевірки: `lessonRules`, `problemsOf`, `passesRules` |
| `lib/queries.dart` | відбір, згортання, групування, пошук накладок |
| `lib/ordering.dart` | порядки сортування й комбінатори `chain`, `descending`, `arranged` |
| `lib/factories.dart` | замикання: лічильник викликів, фабрики умов |
| `lib/summary.dart` | складання тексту звіту |
| `test/schedule_test.dart` | 13 тестів |

Чому саме така структура: код поділено за тим, за що він відповідає, а
залежності йдуть в один бік (налаштування → регулярні вирази → час →
розбір і правила → вибірки → вивід), тому циклічних імпортів немає. Крім
того, у ЛР 2 реалізацію можна замінити на класи, не чіпаючи точку входу.
Код із `bin/` не можна підключити з тестів, тому в ньому нічого, крім
викликів.

## Типи даних і чому саме такі

**Заняття — іменований запис, а не `Map`.**

```dart
typedef Lesson = ({String subject, String lecturer, String kind,
  int weekday, int startMinutes, String room, int pairs, DateTime addedOn});
```

Помилка в назві поля не компілюється. У `Map<String, Object>` вона
виявилася б лише під час запуску. Класи заборонені умовою, тому запис —
найближче до «структури з полями». *Альтернатива:* `Map` — гнучкіше, але
без перевірки типів компілятором.

**Час — число хвилин від початку доби** (`09:30` → `570`). Тривалість,
додавання пари, порівняння й позиція в тижні — звичайна арифметика на
цілих. *Альтернатива:* `TimeOfDay` є лише у Flutter, а власний тип — це
клас.

**День тижня — число 1–7**, як у `DateTime.weekday`. Не потрібне
перетворення, коли шукаємо найближче заняття. *Альтернатива:* текстові
назви днів — довелося б мати мапу назв і розбирати «середа» окремо.

**Результат розбору — `Decoded = (Lesson?, String?)`:** або заняття, або
причина відмови. Зламаний рядок у наборі даних — звична ситуація, а не
аварія, тому `try/catch` не потрібен: поля читаються через `tryParse`, а
`switch` за кортежем повертає першу знайдену причину. *Альтернатива:*
кидати виняток на кожен поганий рядок і ловити його в циклі.

**Правило перевірки — запис із двох функцій** (`holds` і `explain`), а всі
правила — список. Щоб додати вимогу, треба дописати один елемент, а
`problemsOf` і `passesRules` не змінюються. Перевіряються: формат
«Прізвище І.Б.», дозволений тип, навчальний день (1–6), збіг часу із сіткою
пар, формат аудиторії, кількість пар від 1 до 32. *Альтернатива:* одна
велика функція з купою `if`.

**Сортування — маленькі порядки** (`byWeekTime`, `byLecturer`, `byPairs`)
і комбінатори: `chain` переходить до наступного критерію, лише якщо
попередні вважають заняття однаковими, `descending` перевертає порядок.
*Альтернатива:* один компаратор із вкладеними умовами й прапорцями, який
важко читати й розширювати.

**Групування — універсальна `bucket<K>`** з довільним ключем. На ній
побудовані `bySubject`, гістограма типів і пошук накладок (`clashes`:
заняття з однаковим «день + час + аудиторія»). *Альтернатива:* окрема
функція групування на кожен випадок.

**Дозволені типи занять — `Set<String>`**: швидка перевірка «чи є такий
тип».

**Дати — в UTC.** У локальному часі 25.10.2026 змінюється час, і різниця
між двома датами може вийти 25 годин, тоді `inDays` помилиться на добу.
Окремо: `DateTime.utc(2026, 2, 30)` не кидає помилку, а перетворює дату на
2 березня, тому `readIsoDate` порівнює місяць і день після створення.

## Залежності

У `dependencies` порожньо. Шаблон `dart create -t console` додає `path`,
але вона не потрібна, тому прибрана. У `dev_dependencies`:

| Пакет | Навіщо | Альтернатива |
|---|---|---|
| `lints` | набір правил для `dart analyze` (`recommended`), у `analysis_options.yaml` ще посилено: `strict-casts`, `strict-inference`, `strict-raw-types`, `public_member_api_docs` та інші | `flutter_lints` — для Flutter, а проєкт консольний; або взагалі без лінтів — тоді аналізатор бачить менше |
| `test` | модульні тести розбору, правил, групування, сортування, дат | писати власні перевірки на `assert` — немає груп і зручного звіту |

Інші популярні пакети не знадобилися, бо потрібне вже є в Dart:

* `collection` — `firstOrNull` і `indexed` є в `dart:core`, групування
  зроблено через `fold`;
* `intl` — для виводу вистачає `padLeft` і `DateTime`;
* `path` — шляхів до файлів у цій роботі немає.

## `!`, `late`, `dynamic`

У коді їх немає. `null` обробляється через зіставлення зі зразком
(`(final weekday?, final start?, …)`), `?.` та `??`.
