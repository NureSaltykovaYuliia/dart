# Розклад занять академічної групи (group_schedule)

Лабораторна робота №1 з дисципліни «Програмування мовою Dart».  
Варіант 4: **«Розклад занять групи»** (атрибути заняття: дисципліна, викладач, тип заняття, день тижня, час початку, номер аудиторії).

Консольна програма виконує синтаксичний аналіз вхідних CSV-рядків, відсіює некоректні дані, валідує записи комплексом правил, обчислює аналітичні показники розкладу, ідентифікує колізії аудиторій та генерує форматований звіт про найближчі пари.

> **Важливе обмеження:** Згідно з методичними вказівками до першої лабораторної роботи, класи в проєкті **не використовуються**. Уся бізнес-логіка побудована на записах (records), функціях першого класу, замиканнях та колекціях стандартної бібліотеки.

---

## Інструкція із запуску

```bash
dart pub get                                 # завантаження залежностей
dart run                                     # формування звіту на поточну дату й час
dart run bin/group_schedule.dart 2026-10-15  # контрольний запуск на фіксовану дату (детермінований результат)
dart analyze                                 # перевірка коду статичним аналізатором
dart test                                    # запуск комплексу модульних тестів
```

> **Примітка щодо кодування шляху:** Якщо в шляху до кореневого каталогу містяться нелатинські символи, утиліта `dart test` у версії SDK 3.13 може повідомляти про помилку резолвінгу пакета в `package_config.json`. При виконанні у каталозі з суто латинським шляхом усі тести проходять штатно.

## Специфікація вхідних даних

Вхідні рядки передаються у напівструктурованому форматі з розділювачем `;`:

```
дисципліна;викладач;тип;день;час;аудиторія;пар;внесено
Програмування мовою Dart;Петренко О.В.;лекція;1;09:30;287;16;2026-08-28
```

- **День тижня** задається цілим числом відповідно до `DateTime.weekday` (від `1` — понеділок до `7` — неділя).
- Для повноти аналізу модель доповнена двома числовими атрибутами: кількістю пар за семестр (використовується для агрегації навантаження, підрахунку середнього та екстремумів) та датою реєстрації запису (для розрахунку давності).

Тестовий набір у `lib/timetable_rows.dart` містить **18 рядків**:
- **12 валідних** записів;
- **4 синтаксично пошкоджених** (бракує обов'язкового стовпця, текстова назва дня «середа» замість цифри, некоректний роздільник у часі `9.30`, неіснуючий день календаря `2026-02-30`);
- **2 семантично некоректних** (розпізнаються успішно, але відхиляються валідатором через порушення правил предметної області).

### Архітектурні особливості

- **Модульне розділення:** Логіка повністю винесена з `bin/` до модулів `lib/`. Каталог `bin/` містить лише послідовність викликів. Залежності між файлами орієнтовані суворо в один бік (`settings/lesson → patterns → clock → decode/rules → queries/ordering → summary → bin`), що унеможливлює циклічні зв'язки.
- **Декларативні правила валідації:** Перевірка побудована у вигляді списку конфігурацій `({LessonTest holds, String Function(Lesson) explain})`. Додавання нового правила не потребує редагування логіки перевірки у функціях `problemsOf` чи `passesRules`.
- **Функціональна композиція сортування:** Замість складної умови з вкладеними прапорцями реалізовано незалежні атомарні порядки (`byWeekTime`, `byLecturer`, `byPairs`) і комбінатори `chain` (послідовне застосування критеріїв) та `descending` (інверсія напрямку).

## Обґрунтування вибору структур даних

- **Іменовані записи (`records`) замість `Map<String, Object>`:** Записи забезпечують строгий контроль типів на етапі компіляції, незмінність та порівняння за значенням без оверхеду повноцінних класів.
- **Час у хвилинах від початку доби (`int startMinutes`):** Дозволяє виконувати прямі арифметичні обчислення тривалості, спрощує визначення перетинів і знаходження найближчої пари у тижневій шкалі (`weekMinute`).
- **Числове кодування дня тижня (`int weekday` 1–7):** Повністю узгоджується з властивістю `DateTime.weekday` ядра Dart, що робить розрахунок найближчої дати заняття простою операцією за модулем тижня.
- **Тип результату розбору `Decoded = (Lesson?, String?)`:** Позиційний кортеж передає або успішно розпібране заняття, або опис причини помилки. Застосування `try/catch` виключено: пошкоджені дані обробляються як стандартний сценарій через `tryParse` та зіставлення зі зразком (`switch`).
- **`Set<String> knownKinds` для категорій:** Перевірка належності типу заняття до списку дозволених виконується за сталий час $O(1)$.
- **Робота з датами в `UTC`:** Запобігає похибкам через сезонне переведення годинників (наприклад, 25 жовтня 2026 року), гарантуючи сталу тривалість доби у 24 години при підрахунку днів через `difference().inDays`.

## Зовнішні залежності

| Пакет | Область | Обґрунтування |
|---|---|---|
| `lints` | dev | Офіційний набір рекомендованих правил аналізатора Dart відповідно до стандартів платформи |
| `test` | dev | Інструментарій автоматизованого модульного тестування функцій парсингу, валідації та запитів |

Сторонні бібліотеки (`intl`, `collection`, `path`) свідомо не залучалися:
- методи `firstOrNull`, `indexed` доступні в ядрі Dart;
- операції групування реалізовано через стандартний `fold`;
- форматування чисел і дат реалізовано засобами `padLeft` та вбудованого `DateTime`.

## Чистота та надійність коду

У реалізації повністю відсутні:
- примусове розгортання `!`;
- відкладена ініціалізація `late`;
- динамічна типізація `dynamic`.

Усі nullable-значення перевіряються через зіставлення зі зразком (`pattern matching`) та оператори безпечної навігації (`?.`, `??`).
