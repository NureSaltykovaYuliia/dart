# ЛР 3 — Асинхронність: Future, Stream, ізоляти (group_schedule_async)

Третя лабораторна, варіант 4. Модель з ЛР 2 залишилась без змін, а
навколо неї з'явилися:

* асинхронне сховище `AsyncRepository` на `Future`;
* потік подій розкладу на `Stream` (`StreamController`);
* важке обчислення, винесене в окремий ізолят.

Диск і мережа тут імітуються затримками `Future.delayed`. Справжні файли й
HTTP — у ЛР 4.

## Запуск

```bash
dart pub get
dart run        # усі демонстрації з виводом і вимірюваннями
dart analyze
dart test       # 28 тестів
```

28 тестів — це 16 з ЛР 2 (`model_test.dart`) і 12 нових
(`async_test.dart`: `group`, `setUp`, `expectLater`, тест на помилку й
тест на порядок подій).

## Як влаштований код

| Файл | Що в ньому |
|---|---|
| `bin/group_schedule_async.dart` | точка входу, демонстрації по кроках методички |
| `lib/async_repository.dart` | `AsyncRepository<T extends Identifiable>`: `load`, `save`, `delete`, `loadAll`, `watchAll` (`async*`) |
| `lib/events.dart` | `sealed class ScheduleEvent` (`LessonAdded`, `RoomChanged`, `LessonCancelled`) і `ScheduleEvents` на `StreamController` |
| `lib/heavy.dart` | `countPrimes` — решето Ератосфена, запуск через `Isolate.run` |
| решта `lib/` | модель з ЛР 2 без змін |

У `bin/` лише послідовність демонстрацій, уся логіка — в `lib/`, щоб її
можна було тестувати.

## Чому так

**Сховище імітує диск затримкою.** Параметр `latency`: 300 мс за
замовчуванням, 5 мс у тестах, щоб вони не чекали. Для «пошкоджених»
ідентифікаторів `load` завершується `StorageException`.
*Альтернатива:* справжній файл — це ЛР 4; тут потрібна лише керована
затримка.

**`Future` для разових операцій, `Stream` для послідовності.**
`load`/`save`/`delete` дають одне значення, а `watchAll` віддає сутності
по одній. Генератор `async*` ледачий: тіло виконується, лише коли хтось
підписався (у демонстрації тіло не стартувало навіть через 100 мс після
створення потоку). *Альтернатива:* `loadAll` повертає весь список одразу,
і він теж є, але потік не тримає все в пам'яті.

**Лінти `unawaited_futures` і `discarded_futures`.** Увімкнені в
`analysis_options.yaml`: забутий `await` стає зауваженням аналізатора.
Навмисні місця в демонстраціях позначені
`// ignore: unawaited_futures`. Демонстрація «забутого await» показує
причину: без `await` одразу після `save` у сховищі 0 записів, а через
затримку стає 1.

**`Future.wait` проти `.wait`.** Для кількох одночасних операцій
`Future.wait` повертає лише першу помилку й губить результати, а
розширення `.wait` кидає `ParallelWaitError` з частковими значеннями й
усіма помилками. Тому для діагностики використано `.wait`. Три операції по
500 мс: 1541 мс послідовно проти 513 мс разом.

**`sealed class ScheduleEvent`.** Три підтипи подій; `switch` у
`describeEvent` вичерпний, і новий тип події не можна «забути» обробити.

**Потік одноразової підписки за замовчуванням.** Він запам'ятовує події,
доки не з'явиться слухач (корисно для журналу). Якщо слухачів кілька, є
`ScheduleEvents(broadcast: true)`: другу підписку на звичайний потік
блокує `Bad state: Stream has already been listened to.`, а широкомовний
не зберігає події, додані до підписки.

**Кожну підписку скасовують явно:** `listen` повертає
`StreamSubscription`, який зберігається й закривається через `cancel()`.

**Ізолят — лише для справді важкого обчислення** (прості числа до
40 000 000). Одне обчислення в `Isolate.run` не швидше: 3266 мс синхронно
проти 3268 мс. Різниця в тому, що головний ізолят лишається живим:
найбільша пауза між тиками таймера 110 мс замість 3275 мс. Виграш у часі
видно, коли обчислень кілька: чотири — 11 890 мс послідовно проти
6 564 мс у чотирьох ізолятах. Ізолят працює з копією пам'яті: змінена в
ньому глобальна змінна в головному не змінюється.

## Залежності

Для запуску пакетів із pub.dev немає: вистачає `dart:async` і
`dart:isolate`. Для розробки:

| Пакет | Навіщо | Альтернатива |
|---|---|---|
| `lints` | правила аналізатора, зокрема `unawaited_futures` і `discarded_futures` | `flutter_lints` — для Flutter |
| `test` | `group`, `setUp`, `expectLater`, `emitsInOrder`, `emitsError` для тестів потоків і `Future` | `flutter_test` — працює лише у Flutter |

Окремі пакети для асинхронності (наприклад, `rxdart` для потоків) не
підключались: усе потрібне за завданням — `Future`, `Stream`,
`StreamController`, `async*`, ізоляти — є в самому Dart.

## `!`, `late`, `dynamic`

`!` і `dynamic` не вживаються. `late` є лише в тесті (`late
AsyncRepository<Lesson> repo;`): змінну ініціалізує `setUp` перед кожним
випробуванням. Без `late` довелося б писати `AsyncRepository<Lesson>? repo`
і перевіряти на `null` у кожному тесті.

## Нове в Dart

Приватний іменований параметр `this._brokenIds` у конструкторі
`AsyncRepository` (Dart 3.12+) — без проміжної змінної.
